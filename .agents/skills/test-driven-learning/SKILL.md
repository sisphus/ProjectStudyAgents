# Test Driven Learning Skill

Use this skill to turn the project specification into executable understanding.

## Instructions

1. Extract behavior rules from `SPEC.md`.
2. Convert each rule into tests or test ideas.
3. Explain what concept each test teaches.
4. Explain what bug each test catches.
5. Use official tests first.
6. Add minimal custom tests only when useful.
7. Consider edge cases, repeated operations, invalid inputs, concurrency, persistence, recovery, stale state, idempotency, and cleanup.
8. Record stable commands in `docs/commands.md`.
9. Connect new terms or concepts to `docs/glossary.md` when useful.

Do not create large test suites before understanding the official testing approach. Prefer the smallest test that exposes the rule being learned.

### Test Idea
